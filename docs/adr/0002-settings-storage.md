# 0002. 設定の保存先をPropertiesServiceからスプレッドシートのタブへ変更する

## ステータス
承認済み

## コンテキスト

管理者設定画面（所定労働時間、パスワード最低文字数、セッション有効期限、
会社の休日カレンダーID、有休の付与・失効パラメータ）の値は、GAS版では
`PropertiesService`（スクリプトプロパティ）に保存していた。

[0001](0001-execution-layer-migration.md)でVercel Functionsへ移行するにあたり、
Vercel Functionsはステートレスなサーバーレス関数で、GASの`PropertiesService`に
相当する永続ローカルストレージを持たない。加えて、GAS側でも
「データはスプレッドシートのまま」という方針（0001参照）に合わせるなら、
設定だけ別の場所（スクリプトプロパティ）に置いたままにしておく理由が薄い。

## 検討した選択肢

- **選択肢A: Vercel側だけ何らかの外部ストア（Upstash Redis等）に保存する**
  GAS側とデータ形式・保存場所が分かれてしまい、移行時に値を手動で
  コピーする手間が生じる。追加の外部サービス契約も必要になる。
- **選択肢B（採用）: 同じスプレッドシート内に`settings`シート（key/value）を
  作り、GAS・Vercelの両方がそこを読み書きする**
  `users`/`devices`シートと同じ「スプレッドシートに全データを置く」方針に
  揃えられる。GAS側を先にこの方式に変えておけば、Vercel移行時に設定値を
  別途移す作業が要らない（そのまま同じシートを読むだけ）。

## 決定

`settings`シート（見出し行 `key` | `value`、`devices`シートと同じく初回アクセス時
に自動生成）を追加し、GAS・Vercelどちらのバックエンドも同じスプレッドシート内の
このシートを読み書きする。未設定のキーはコード内の既定値
（`SETTINGS_DEFAULTS`）を使う。この変更はVercelへの切り替えを待たず、GAS側に
先行して適用した（本番で動作確認済み）。

## 結果・トレードオフ

**得られるもの**: 設定データも他のデータと同じくスプレッドシート上で完結し、
Vercelへの切り替え時に追加の移行作業が不要になる。GAS版のパスワード最低文字数
などの値も、シート移行時にそのまま引き継がれた。

**引き換えに受け入れるコスト**: `PropertiesService`より読み書きがわずかに遅い
（スプレッドシートAPI呼び出しになるため）。ただし設定は書き込み頻度が低く、
読み込みもキャッシュしていない現状で許容範囲と判断した。
